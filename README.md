# GoAdmin 项目结构

本项目基于 Gin + GORM 搭建，划分为 `api` 与 `admin` 两个模块，采用分层设计，便于维护与扩展。

## 顶层目录
- `cmd/`：各模块的入口程序（例如 `cmd/api`, `cmd/admin`）。负责加载配置、初始化依赖并启动服务。
- `internal/`：核心业务代码，分模块存放。
  - `internal/api/`：面向外部 API 的控制器、服务、路由、中间件等。
  - `internal/admin/`：后台管理相关的控制器、服务、路由、中间件等。
  - `internal/common/`：跨模块复用的模型、仓储、配置等基础能力。
- `pkg/`：通用工具库（配置、数据库、日志、响应封装、工具集等），可在多个模块间共享。
- `configs/`：配置文件存放位置，支持多环境切换。
- `docs/`：接口文档、设计文档等。
- `migrations/`：数据库迁移脚本。
- `scripts/`：项目运维或开发辅助脚本。
- `testdata/`：测试所需的样例数据。
- `main.go`：简单示例入口，可在 `cmd` 目录下逐步替换为模块化启动方式。

## 内部结构建议
- **Controller**：仅负责请求解析与响应返回。
- **Service**：承载业务逻辑，协调仓储、第三方服务等。
- **Repository**：使用 GORM 管理数据库访问，实现数据持久化。
- **Middleware**：鉴权、日志、限流等横切能力。
- **DTO/Model**：定义请求/响应数据结构、数据库实体。

## 后续步骤
- 在 `cmd/api` 与 `cmd/admin` 中实现各自的 `main.go`，加载对应路由与服务。
- 在 `configs/` 添加多环境配置，并在启动时选择加载。
- 补充数据库模型与迁移脚本，完善 `pkg/database` 初始化逻辑。

以上结构为建议的基础骨架，可根据业务需要调整与扩展。
